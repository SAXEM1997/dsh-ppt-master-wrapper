## 总结

本版把发版流程从「合 PR 后手工打 tag、再触发 stage 发布并等 2FA 批准」改为 **tag 驱动**：推送附注 tag 后，`release.yml` 依次完成门禁、npm 发布、产物校验与 GitHub Release。门禁覆盖 tag 与 manifest 一致性、release notes、四处版本记账、附注 tag 且位于 main、vendor 文件完整性、stub 树全套与打包检查；发布后用本地打包的 sha1 与 registry `dist.shasum` 比对，确认 tag 的树与该版本已发布的字节一致。初版流水线中同义反复的 shasum 校验、缺失的 `PLUGIN_VERSION` 与 vendor 完整性检查一并修正。`publish.yml` 保留为 token 受 npm 2FA 新政影响时的兜底，GitLab 镜像推送仍为手工。本版不改变插件运行时行为。

## Summary

This release moves publishing from "tag by hand, then trigger a staged publish and wait for 2FA approval" to **tag-driven**: pushing an annotated tag runs `release.yml`, which applies the gates, publishes to npm, verifies the artifact and creates the GitHub Release. The gates cover tag/manifest agreement, release notes, the four version bookkeeping places, an annotated tag on `main`, vendor completeness, the full stub suite and packaging; after publishing, the sha1 of a local pack is compared with the registry's `dist.shasum`, proving the tag's tree is the artifact users install. The initial pipeline's tautological shasum check and the missing `PLUGIN_VERSION` and vendor-completeness gates are fixed as well. `publish.yml` remains the fallback if the token is affected by npm's 2FA policy; the GitLab mirror is still pushed by hand. No runtime behaviour changes.

## Changes

- #84 Add the tag-triggered `release.yml`, replacing the manual stage + 2FA primary path.
- #85 Move the `npm whoami` preflight ahead of the notes gate.
- #86 Let dry runs take `source_ref`, so the whole pipeline can be rehearsed on `main`.
- #87 Replace the tautological shasum check with a local-pack sha1 vs registry `dist.shasum` comparison.
- #88 Add the `PLUGIN_VERSION`, annotated-tag/on-`main` and vendor-completeness gates, and serialise reruns.
